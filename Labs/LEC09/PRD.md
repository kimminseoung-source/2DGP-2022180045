# 소닉 애니메이션 뷰어 개발 요구사항 문서

## 1. 문서 목적

`PRE-PRD.md`를 바탕으로 소닉 스프라이트 시트의 모든 동작을 순서대로 보여 주는 애니메이션 뷰어의 구현 요구사항, 개발 단계, 검수 기준을 정의한다.

사용자는 프로그램을 실행하는 것만으로 확대된 소닉의 동작을 관찰할 수 있어야 한다. 각 동작은 5회 재생한 후 0.5초간 쉬고 다음 동작으로 넘어가며, 전체 순서는 종료 입력이 있을 때까지 무한 반복한다.

## 2. 개발 환경과 산출물

| 항목              | 요구사항                                                         |
| ----------------- | ---------------------------------------------------------------- |
| 개발 언어         | Python 3                                                         |
| 그래픽 라이브러리 | pico2d                                                           |
| 실행 파일         | `sonic_animation_viewer.py`                                    |
| 구현 구조         | 실행 코드, 프레임 정보, 재생 로직을 위 Python 파일 하나에 작성   |
| 입력 이미지       | 실행 파일과 같은 폴더의`sonic-sprite.png`                      |
| 실행 방법         | 해당 파일을 Python으로 실행하거나 VS Code의 Run Python File 사용 |
| 개발 기록         | 기능을 점진적으로 추가하는 최소 20단계와 단계별 한글 Git 커밋    |

PRE-PRD에는 이미지명이 `sonic sprite.png`로 기재되어 있지만, 현재 제공된 파일은 `sonic-sprite.png`이다. 구현에서는 실제 파일명을 사용한다. 이미지와 문서는 단일 Python 파일 제약의 대상이 아니며, 실행에 필요한 사용자 정의 Python 모듈이나 별도 프레임 데이터 파일은 추가하지 않는다.

## 3. 범위와 해석 기준

### 3.1 포함 범위

- 제공된 시트에서 소닉의 동작을 표현하는 모든 프레임을 조사하고 재생한다.
- 동작별 프레임 목록과 재생 순서를 코드 내부에 정의한다.
- 각 동작의 5회 반복, 동작 사이의 0.5초 대기, 전체 동작의 무한 순환을 구현한다.
- 캐릭터를 충분히 확대하여 표시한다. 제자리 동작은 화면 중앙 부근에, 이동 가능한 동작은 화면 안에서 수평 이동하도록 표시한다.
- 재생 및 대기 중 창 닫기와 Esc 종료 입력을 처리한다.

### 3.2 제외 범위

- 사용자 입력에 의한 플레이어 조작, 충돌, 점수, 스테이지 등 게임 기능
- 소리, 이미지 편집, 새로운 스프라이트 제작
- 재생 속도 조절, 동작 선택 메뉴, 일시 정지 버튼
- 제목, 제작자 표기, 장식 및 소닉 동작이 아닌 다른 캐릭터의 그림

### 3.3 구현을 위한 기본 해석

다음 사항은 원문에서 세부 방식이 정해지지 않아 이 문서에서 채택한 기준이다.

- “모든 동작”은 이미지의 행 개수가 아니라 포즈 변화와 연속성이 구분되는 소닉 동작 묶음을 뜻한다. 한 행에 여러 동작이 있으면 분리하고, 여러 행에 걸친 하나의 동작은 연결한다.
- 독립된 소닉 포즈도 빠뜨리지 않는다. 연속 동작으로 묶을 근거가 없으면 1프레임 동작으로 등록한다.
- 제목과 하단 크레딧 및 다른 캐릭터는 재생 대상에서 제외한다.
- “0.5초 쉬기”는 현재 동작의 마지막 프레임을 유지하는 것으로 해석한다.
- 마지막 동작도 5회 재생 후 0.5초 대기하고 첫 동작으로 돌아간다.
- 원본 스프라이트의 픽셀과 투명도는 수정하지 않는다. 무대 배경과 시각 효과는 실행 중 도형 및 원본 프레임의 투명도 조절로 표현한다.

정확한 동작 수, 이름, 프레임 수 및 잘라내기 좌표는 첫 개발 단계에서 이미지 전체를 조사하여 확정한다. 외부 게임의 애니메이션 명칭이나 고정 격자를 근거 없이 적용하지 않는다. 이름이 불분명하면 포즈를 설명하는 한글 이름 또는 `동작 01`처럼 중립적인 이름을 사용한다.

## 4. 기능 요구사항

### FR-01. 실행과 이미지 로딩

- 프로그램 시작 시 pico2d 캔버스를 열고 이미지를 로드한다.
- 이미지 경로는 실행 파일의 위치를 기준으로 계산한다. 터미널의 현재 작업 폴더가 달라도 실행되어야 한다.
- 이미지가 없거나 로드할 수 없으면 파일명과 원인을 알 수 있는 오류를 출력하고 종료한다.
- 정상 시작 시 첫 동작의 첫 프레임부터 자동으로 재생한다.

### FR-02. 동작 및 프레임 정의

- 각 동작에는 이름, 순서가 있는 프레임 목록, 프레임 재생 속도를 정의한다.
- 각 프레임에는 원본 이미지에서의 잘라내기 영역과 위치 정렬에 필요한 기준점을 정의한다.
- 프레임 크기와 동작별 프레임 개수가 달라도 처리할 수 있어야 한다.
- 좌표가 원본 이미지 범위를 벗어나지 않도록 확인한다.
- 이미지 상단 기준으로 좌표를 기록하는 경우 pico2d의 하단 기준 좌표로 변환하여 사용한다.
- 동작 목록 작성 후 이미지의 모든 소닉 프레임이 목록에 포함되었는지 대조한다. 제외한 그림은 제외 이유를 기록한다.

### FR-03. 한 동작의 재생

- 동작의 프레임은 등록된 순서대로 재생한다.
- 제자리 동작의 기본 재생 속도는 초당 10프레임으로 한다. 걷기·가속·몸 회전·공 회전·달리기·빠른 달리기는 각각 12·16·16·18·16·20 FPS로 재생한다.
- 프레임 하나가 정해진 표시 시간을 채운 후 다음 프레임으로 넘어간다.
- 첫 프레임부터 마지막 프레임까지 모두 표시한 것을 1회 재생으로 계산한다.
- 마지막 프레임의 표시 시간이 끝난 시점에 완료 횟수를 증가시킨다.
- 1프레임 동작도 해당 프레임의 표시 시간마다 1회로 계산하여 총 5회 재생한다.

### FR-04. 5회 반복과 대기

- 현재 동작을 정확히 5회 재생한다.
- 1~4회 완료 시 같은 동작의 첫 프레임으로 돌아간다.
- 5회 완료 시 추가 반복 없이 0.5초 대기 상태로 전환한다.
- 대기 중에는 마지막 프레임을 화면에 유지한다.
- 대기 시작부터 0.5초가 경과한 후 다음 동작의 첫 프레임으로 전환한다. 동작 및 반복 횟수와 타이머를 초기화한다.
- 대기를 위해 이벤트 처리를 멈추는 0.5초짜리 블로킹 호출을 사용하지 않는다.

### FR-05. 전체 동작의 무한 반복

- 등록된 동작을 목록 순서대로 모두 재생한다.
- 마지막 동작의 대기 종료 후 첫 동작으로 돌아간다.
- 순환 경계에서 동작이 누락되거나 반복 횟수 또는 대기 시간이 누적되지 않아야 한다.
- 사용자 종료 입력이 없으면 순환을 계속한다.

### FR-06. 확대와 배치

- 기본 창 크기는 1200×800픽셀로 한다.
- 제자리 동작은 화면 중앙 부근에 배치한다. 이동 동작의 시작 위치도 같은 기준점을 사용하며, 재생 중에는 안전 범위 안에서 이동한다. 가로·세로에 동일한 확대 배율을 적용한다.
- 전체 프레임의 최대 가로·세로 크기를 이용해 하나의 공통 배율을 계산한다. 가장 큰 프레임이 창 가로 또는 세로의 약 60%를 차지하도록 하되 모든 프레임이 화면 안에 들어와야 한다. 현재 시트에서는 약 10.67배로 확대하며 최대 프레임 높이는 480픽셀이다.
- 확대 배율은 동작 전환이나 프레임 전환 때 변경하지 않는다.
- 프레임별 기준점을 맞춰 걷기·달리기 등의 재생에서 캐릭터가 불필요하게 흔들리지 않도록 한다. 의도한 수평 이동은 별도의 위치 값으로 관리하며, 원본 동작 자체의 높이 변화는 유지한다.
- 주변 프레임, 제목, 크레딧이 잘라내기 영역에 섞이지 않아야 한다. 팔다리와 동작 효과도 잘리지 않아야 한다.
- 배경은 짙은 남색 그라데이션과 청록색 수평 기준선·원근 바닥 격자로 구성한다. 캐릭터를 따라가는 바닥 그림자로 이동과 접지 위치를 보여 준다.

### FR-07. 종료와 자원 정리

- 창 닫기 또는 Esc 입력 시 재생 루프를 종료한다.
- 재생 중과 대기 중 모두 종료 입력에 응답한다.
- 종료 시 열린 캔버스를 정리한다. 로딩 실패 시에도 가능한 자원 정리를 수행한다.

### FR-08. 이동 동작의 수평 이동

- 걷기·가속·몸 회전·공 회전·달리기·빠른 달리기에 자동 수평 이동을 적용한다. 나머지 동작은 제자리에서 재생한다.
- 이동 속도는 화면 픽셀/초 기준으로 각각 180·340·300·420·460·680으로 한다. 재생 FPS와 별도로 설정하며, 걷기보다 달리기와 빠른 달리기가 빠르게 이동해야 한다.
- 오른쪽을 향해 이동하다 안전 범위의 끝에 도달하면 왼쪽으로 이동하며 이미지를 좌우 반전한다. 왼쪽 끝에서도 같은 방식으로 오른쪽으로 돌아선다.
- 이동 가능한 범위는 해당 동작의 모든 프레임 크기와 몸통 기준점, 공통 확대 배율 및 양쪽 방향을 고려하여 계산한다. 팔다리·효과를 포함한 프레임 전체와 화면 가장자리 사이에 최소 48픽셀을 확보한다.
- 같은 동작의 1~5회 반복 중에는 위치와 진행 방향을 유지하여 연속으로 이동한다.
- 5회 완료 후 0.5초 대기 중에는 마지막 프레임·위치·방향을 유지한다.
- 다음 동작으로 전환할 때 위치를 기본 중앙 기준점으로 초기화하고 오른쪽을 향하게 한다. 마지막 동작에서 첫 동작으로 돌아갈 때도 동일하다.
- 이동 거리는 실제 경과 시간으로 계산한다. 긴 시스템 지연에서는 프레임 시간 한 구간에 해당하는 이동량까지만 적용하여 순간이동을 방지한다.

### FR-09. 현재 동작 표시와 시작 동작 선택

- 창 제목에 현재 동작명, 제자리/오른쪽 이동/왼쪽 이동/0.5초 대기 상태 및 반복 횟수를 표시한다.
- 기본 실행은 기존 동작 순서를 유지한다. 정상 속도에서 처음 약 7.5초는 제자리 동작이며, 이후 걷기부터 이동한다. 시스템 지연이 있으면 시작 시간이 늘어날 수 있다.
- `--start-animation 걷기`처럼 시작 동작을 지정할 수 있어야 한다. 해당 동작을 첫 번째로 오도록 목록을 순환 배치하며 전체 15동작·76프레임과 동작별 5회 반복·0.5초 대기 규칙을 유지한다.

### FR-10. 역동적인 화면 연출

- 이동 중에는 이전 프레임의 위치와 방향을 저장해 최대 5개의 짧은 잔상을 표시한다. 생성 간격은 약 0.045초, 수명은 0.24초이며 시간이 지날수록 투명하게 한다.
- 잔상을 그린 뒤 원본 본체를 완전히 불투명하게 표시한다. 다른 동작이나 이후 프레임에 잔상 투명도가 남지 않아야 한다.
- 이동 방향 뒤쪽에 속도선을 표시하고, 바닥 격자를 이동과 반대 방향으로 천천히 흘려 속도감을 표현한다.
- 제자리 동작과 0.5초 대기 중에는 잔상과 속도선을 표시하지 않는다. 대기 중에는 바닥의 이동도 정지한다. 다음 동작으로 넘어갈 때 이전 동작의 잔상을 제거한다.
- 배경과 잔상은 재생 횟수·동작 순서·대기 시간에 영향을 주지 않아야 한다. 별도 이미지 파일이나 실행용 Python 모듈을 추가하지 않는다.

## 5. 재생 상태와 시간 처리

재생 로직은 최소한 현재 동작 번호, 프레임 번호, 완료 횟수, 현재 상태, 프레임 경과 시간, 대기 경과 시간, 수평 위치 및 진행 방향을 관리한다. 위치 갱신은 재생 상태에서만 수행하며, 다음 동작으로 넘어갈 때 위치와 방향도 초기화한다.

| 현재 상태 | 전환 조건                                     | 처리 및 다음 상태                                                 |
| --------- | --------------------------------------------- | ----------------------------------------------------------------- |
| 재생      | 일반 프레임 표시 시간 종료                    | 다음 프레임 표시, 재생 유지                                       |
| 재생      | 마지막 프레임 표시 시간 종료, 완료 횟수 1~4회 | 완료 횟수 증가 후 첫 프레임 표시                                  |
| 재생      | 마지막 프레임 표시 시간 종료, 완료 횟수 5회   | 마지막 프레임 유지, 대기 시간 0으로 설정 후 대기                  |
| 대기      | 대기 시간 0.5초 미만                            | 마지막 프레임 유지, 이벤트 처리 계속                              |
| 대기      | 대기 시간 0.5초 이상                            | 다음 동작 또는 첫 동작으로 이동, 반복·프레임 시간 초기화 후 재생 |
| 모든 상태 | 창 닫기 또는 Esc                              | 루프 종료 및 캔버스 정리                                          |

애니메이션 시간은 루프 실행 횟수 대신 단조 증가하는 시계의 실제 경과 시간으로 계산한다. 목표 프레임 간격은 `1 / FPS`초이다. 한 번의 갱신에서 여러 프레임 경계를 처리해야 하는 경우에도 5회 완료 경계와 대기 전환을 건너뛰지 않는다. 창 이동 등으로 긴 지연이 발생했을 때 화면에 보이지 않은 동작을 연속으로 건너뛰지 않도록 시간 보정 방식을 정한다.

## 6. 코드 품질 요구사항

- 창 크기, 반복 횟수 5, 대기 시간 0.5초, 기본 FPS는 코드 상단의 설정값으로 관리한다.
- 동작 데이터와 이벤트 처리, 시간 갱신, 그리기, 실행 진입점을 구분하여 읽기 쉽게 작성한다.
- 이미지는 시작 시 한 번 로드하며 매 프레임 다시 읽지 않는다.
- 과도한 CPU 사용을 피하도록 렌더링 루프에 짧은 대기 또는 주기 제한을 적용한다. 종료 입력을 처리할 수 없는 긴 대기는 사용하지 않는다.
- 프레임 좌표 체계와 반복 완료 시점처럼 오해하기 쉬운 부분에는 설명을 남긴다.
- 구현과 검증을 위한 사용자 정의 코드는 단일 실행 파일 안에 유지한다. 검증을 위해 별도 Python 파일을 필수 산출물로 만들지 않는다.

## 9. 완료 조건

모든 기능 요구사항과 AC-01~AC-16를 충족하고, 실제 이미지에서 확정한 동작 목록이 실행 파일에 반영되면 개발 완료로 판단한다. 최종 산출물은 단일 실행 파일이며, 제공된 이미지를 같은 폴더에 두면 별도 사용자 조작 없이 전체 동작의 5회 재생·0.5초 대기·무한 반복이 동작해야 한다. 이동 가능한 동작은 안전 범위 안에서 방향에 맞게 왕복 이동하고, 대기 중에는 마지막 위치에 정지해야 한다.
